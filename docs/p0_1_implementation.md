## 行为边界

- 轻击：22 伤害，0.25 / 0.12 / 0.38 秒，消耗 10 精力（按 2026-09-07 用户反馈修改）。
- 重击：48 伤害，20 精力，0.60 / 0.18 / 0.60 秒。
- 攻击最初 0.12 秒允许支付翻滚成本取消；已支付的重击精力不退还。生效和收招不能任意翻滚取消。
- 攻击仅在起手时对 3.2m 内、前方 35° 内目标进行最多 12° 修正；生效瞬间不再追踪转向。
- 翻滚 25 精力；滚动 0.55 秒后进入 0.05 秒起身状态（用户后续从0.15秒调整），起身无额外无敌且不能攻击/翻滚；不增加滑行距离。
- 精力消耗后延迟 0.7 秒恢复，恢复速度 25/s；攻击、滚动和起身期间不恢复。普通移动仍可在耗尽时执行，攻击必须支付成本。
- 动作时钟直接采样轻重击/翻滚/起身动画；每次新动作强制从第 0 帧开始，命中闪色不暂停动画。忙碌期间的攻击输入直接丢弃，避免按键缓存导致收招后自动追加攻击。
- 命中按物理查询体积结算，而非 FBX 三角面碰撞；轻击 2.0×1.6×2.0m，重击 1.7×1.8×2.3m，随固定攻击方向放置。F1 显示同一配置，方便检查距离、方向和遮挡。
- 训练靶具有两个重叠 hurtbox，专用于验证一次命中。循环训练攻击预警 1.15 秒、有效 0.18 秒、收招 1.3 秒、18 伤害；这不是 P0-2 Boss AI。
- 每个攻击 ID 在命中或成功闪避后消费；同一攻击不能等无敌结束后再次击中。命中日志包含 `attack_id` 与结果生命。
- R 为训练重置，不代表实现了整轮复活、Boss 胜败或局内重开规则。

## 结构

`training/training_ground.tscn` 负责组装场地、玩家、训练靶、HUD 和音效。
`player/player.tscn` / `player.gd` 管理移动、输入、动作状态与攻击时钟。
`combat/vitals.gd` 独占生命与防重入判定；`hurtbox.gd` 转交命中；`melee_query.gd` 执行物理查询和遮挡检查。
`player/actor_visual.gd` 驱动导入动作与闪色；`ui/training_hud.gd` 监听信号，菜单通过请求信号交给场景协调器。
所有输入动作保存在 `project.godot`，可以在编辑器 Input Map 中查看和修改。

## 验证方法

`tests/test_p0_1.gd` 在真实 Godot 场景上执行攻击、物理查询、移动、状态与输入回归；不是对参数表做字符串比对。测试报告输出 `test_output/p0_1_results.json`。
包含鼠标捕获的完整检查需在有图形界面的模式运行，headless 后端不支持真实鼠标捕获。

`tests/capture_scene.gd` 对实际 OpenGL 画面取样：待机、轻击、重击、预警、暂停。截图直接来自游戏视口，不通过描述代替画面检查。

初版图形模式回归为 62 项。针对用户反馈追加轻击成本、忙碌连点丢弃、同名动画重播、命中后动作时钟一致、翻滚起身状态与滑移检查，最新结果见 `docs/p0_1_test_results.json`。

起身调整为 0.15 秒并接入 P0-2 后：**78 项游戏回归检查通过；27 项导入骨骼与动画衔接检查通过**。后者由 `tests/test_animation_contract.gd` 对导入 Godot 的实际骨骼采样，检查两只手的独立握点、轻重击与 Boss 收招终点、翻滚→起身和起身→待机边界的骨骼位置与旋转连续性，结果存放在 `docs/animation_test_results.json`。

摘要报告：`docs/p0_1_test_results.json`；场景预览：`docs/p0_1_preview.webp`。额外启动检查已使用 Godot MCP 在 debug 模式执行。

视觉检查采用 Agent Vision 的具体检查项（每项 0–2）：中文字符完整 `TYPE-GLYPH-INTEGRITY` 2；HUD 数据字体 `TYPE-DISPLAY-HUD-SPLIT` 2；中心战斗空间 `COMP-CENTER-CLEAR` 2；边缘安全距离 `COMP-SAFE-EDGE` 2；暂停遮罩 `HIER-PAUSE-SCRIM` 2；预警与攻击轮廓 `COMP-SIL-ACTION` 1（仍为原型动作与方框预警，留待 P0-2 精修）。这是局部画面检查，不是完整美术评级。

人工玩法评价（手感是否足够好、玩家熟悉后是否稳定减少失误）仍需真实玩家试玩；自动测试与画面检查不替代该结论。原始 Excel 的后续阶段和未执行的真人试玩记录保持不变。
